# WG-Chain-Warp (chainproxy)

> **极简、高可用的 Linux 多模式网络代理与链式 WARP 枢纽**  
> 一键将你的自建/商业 WireGuard 或 Socks5 代理与 Cloudflare WARP 串联或独立出站。  
> 支持 **6 种灵活运行模式**：`WG -> WARP`、`Socks5 -> WARP`、`单独 WireGuard`、`单独 Socks5`、`单独 WARP`、`SOCKS5 服务端（本机直连）`。
> 🌐 **支持局域网透明网关（旁路由）**：同局域网设备只需将默认网关和 DNS 设置为本机 IP，即可一键走本机出站，按接口实际前缀自动放行网段！

---

## ⚡ 极速一键安装

在你的 Linux VPS / 软路由 / 物理机（支持 Debian 12/13、Ubuntu 22.04/24.04 amd64）上直接运行：

```bash
curl -sSL https://raw.githubusercontent.com/Grandova/WG-Chain-Warp/main/scripts/install.sh | sudo bash
```

> **提示**：脚本会自动安装最新代理引擎内核、Rust 守护进程及 systemd 开机自启服务，耗时约 10-30 秒。

## 🚀 极速上手：只需两步

安装完成后，在终端直接输入：

```bash
chainproxy
```

即可进入**全中文交互控制面板**：

```text
chainproxy 管理面板
  1. 应用并启动    2. 连通性测试    3. 停止服务
  4. 切换模式      5. 出口节点配置
  6. SOCKS5 服务端（监听/用户）
  7. 运维管理（日志/网关/回滚）
  0. 退出
```

### 多种场景操作指引：

- **场景 A：WireGuard -> WARP 链式代理（默认模式）**
  1. 进入 **`5 → 1`** 导入或粘贴 WireGuard 节点配置；
  2. 进入 **`5 → 3`** 选择 `[1]` 一键自动注册 WARP 出口（或 `[2]` 手动粘贴配置）；
  3. 按 **`1`** 应用配置并启动服务！
  4. 按 **`2`** 执行全链路连通性与分跳测试。

- **场景 B：Socks5 -> WARP 链式中继出海（省流量 / 借冷门地区）**
  1. 按 **`4`** 切换模式为 `[2] Socks5 -> WARP 链式中继代理`（或进入 **`5 → 2`** 导入 Socks5 并在提示时确认切换）；
  2. 进入 **`5 → 2`** 粘贴或输入你的 Socks5 代理信息（支持带有账号密码及特殊字符的完整链接）；
  3. 进入 **`5 → 3`** 选择 `[1]` 一键自动注册 WARP 出口；
  4. 按 **`1`** 应用配置并启动服务！

- **场景 C：单独 WireGuard 直连出站（不带 WARP）**
  1. 按 **`4`** 切换模式为 `[3] 单独 WireGuard 出站 (无 WARP)`；
  2. 进入 **`5 → 1`** 导入或粘贴 WireGuard 节点配置；
  3. 按 **`1`** 应用配置并启动服务！

- **场景 D：单独 Socks5 直连出站（不带 WARP）**
  1. 按 **`4`** 切换模式为 `[4] 单独 Socks5 出站 (无 WARP)`；
  2. 进入 **`5 → 2`** 输入 Socks5 代理链接或 IP:端口；
  3. 按 **`1`** 应用配置并启动服务！

- **场景 E：单独 WARP 直连出站（原生 Cloudflare WARP 出口）**
  1. 按 **`4`** 切换模式为 `[5] 单独 WARP 出站 (原生直连)`；
  2. 进入 **`5 → 3`** 选择 `[1]` 一键自动注册 WARP 出口；
  3. 按 **`1`** 应用配置并启动服务！

- **场景 F：作为局域网透明网关（旁路由 / 全屋多设备无感走代理）**
  1. 进入 **`7 → 4`** 进入局域网透明网关管理菜单；
  2. 按 **`1`** 开启网关功能，系统自动探测并允许当前本机接口的实际局域网网段（如 `192.168.1.0/24`）；
  3. 提示立即应用时回车确认生效；
  4. 在同局域网的手机、电脑或电视盒子上，将网络设置为静态 IP，**默认网关** 和 **首选 DNS** 填入本机 IP（如 `192.168.1.50`），同局域网设备即可直接走本机节点/WARP 出站！

- **场景 G：创建 SOCKS5 服务端，使用本机出口**
  1. 主菜单 **`6`** → **`1`** 设置监听地址与端口，如 `0.0.0.0:1080`、`10.82.160.94:1080` 或 `[::]:1080`。
  2. **`2`** 添加用户名和密码；重复输入已有用户名可修改密码，**`3`** 删除用户。
  3. **`4`** 保存并选择服务端模式，再回主菜单 **`1`** 应用。
  4. 客户端应用填写服务器地址、端口、用户名和密码；无需切换客户端默认网关。

服务端必须至少有一个用户，仅走本机直连，不创建 TUN、不安装策略路由、不改 nftables 或 sysctl。
从透明代理模式切换时，会先撤销本程序原有的代理规则。监听地址应是本机拥有的 IP；NAT 容器监听内网 IP 或 `0.0.0.0`，公网访问仍需面板已有的端口映射。
配置随已提交版本保存，守护服务重启后恢复；增删用户或修改监听后需重新应用，已有代理连接会断开重连。

```bash
curl --socks5-hostname 10.82.160.94:1080 --proxy-user 'alice:你的密码' https://ip.sb
```

单独 SOCKS5 出站模式的链路 DNS 使用 TCP 经 SOCKS5 转发，适用于上游 UDP 不可用的情况；连通性检测包含链路 DNS 解析。普通 UDP 应用及 SOCKS5 → WARP 链式模式仍要求上游支持可用的 UDP ASSOCIATE。

## ✨ 最新特性与功能解读（通俗易懂）

### 1. 🔀 6 种代理模式随心切换 (按 `4`)
- **WG -> WARP 双层链式**：经典双层混淆，前置 WireGuard 隧道 + WARP 干净出口。
- **Socks5 -> WARP 链式中继**：Socks5 前置中继承载 WARP，获取前置同地区 WARP 干净 IP，出站不走普通代理线路，省流省钱。
- **单独 WireGuard 直连出站**：无需 WARP，VPS 全局流量直接由指定 WireGuard 节点出境。
- **单独 Socks5 直连出站**：无需 WARP，VPS 全局流量直接由指定 Socks5 代理出境。
- **单独 WARP 直连出站**：原生直连 Cloudflare WARP。
- **SOCKS5 服务端**：多用户认证、可配置监听地址与端口，客户端通过 SOCKS5 使用本机出口。

### 2. 🔐 智能 Socks5 自动解析与严格隐私脱敏 (菜单 `5 → 2`)
- **智能兼容**：支持 `user:pass@host:port`、`socks5://...`、`host:port:user:pass` 等几乎所有主流厂商与包含任意特殊字符的格式。
- **隐私保护**：密码自动掩码脱敏（`********`），日志与面板均绝不泄露敏感凭证。

### 3. 🌐 Cloudflare WARP 自动开通与配置 (菜单 `5 → 3`)
- **一键极速开通**：内建官方 Cloudflare 注册 API 交互，无需额外安装 Cloudflare 客户端即可秒级生成专有 WARP 账号与密钥。
- **保留地址 (Reserved) 支持**：自动注入与维护 Cloudflare WireGuard 标准 reserved 握手标记，确保握手百分之百成功。

### 4. 🚪 局域网透明网关与旁路由支持 (菜单 `7 → 4`)
- **一键开启/关闭**：随时开启或关闭局域网透明网关功能，同局域网设备只需将网关设为本机 IP 即可走本机出站。
- **自动允许实际 LAN 网段**：自动探测本机物理网卡及其局域网 IPv4 地址，按真实 prefix length 计算并放行同网段客户端（如 `192.168.1.0/24`），无需手动计算子网掩码。
- **智能 DNS 劫持与防泄漏**：客户端将 DNS 设置为网关本机或公共 DNS 均可自动进入代理链防污染解析。
- **系统内核智能自愈**：内核自动开启 IP 转发 (`ip_forward`)、配置宽松反向路径过滤 (`loose rp_filter`)，并关闭 ICMP 重定向 (`send_redirects=0`)，杜绝单臂旁路由常见断流问题。

### 5. 🔍 节点与网关详情一览 (菜单 `7 → 3`)
- 随时进入 **`7 → 3`** 查看当前生效模式、WireGuard 节点、Socks5 节点、WARP 出口及透明网关配置。
- 支持按 **`1`** 或 **`2`** 查看底层 WireGuard 原始配置文本，排错或核对一目了然。

### 6. 🛠️ 容器环境与 TUN 设备自愈 (/dev/net/tun 自动修复)
- 针对 LXC、Docker、Incus 或最小化精简系统缺少 `/dev/net/tun` 设备节点的常见问题，系统在服务启动、配置应用及安装脚本中均自动执行 `modprobe tun` 并通过 `mknod` 创建设备节点，彻底根治 `open /dev/net/tun: no such file or directory` 异常。

### 7. 🧠 链式拓扑智能判定与分跳探测 (按 `2`)
- WARP 流量物理上必须经过前置节点中继封装。
- 只要 WARP 成功连通并呈现对应地区出口，系统即智能判定底层载体正常，彻底避免因前置节点未开启裸公网 NAT 导致的探测误报。单独模式下亦能智能适配对应的单跳检测。

### 8. 🛡️ 入站连接物理回程保护 (conntrack 0x88 保护)
- 外部连入本机的 SSH/HTTP 连接使用 conntrack mark 0x88，在 route OUTPUT 中恢复 packet mark 后查 main 表回程；物理链路及外部防火墙仍需正常工作。

### 9. ⏱️ 30 秒看门狗自动回滚 (异常可菜单 `7 → 5` 手动回滚)
- 任何网络变更都有安全看门狗兜底。若链路应用后出现网络断联，看门狗将在 30 秒内全自动回滚到初始网络状态，安全无忧。

### 10. 📜 日志等级调节与实时日志中心 (菜单 `7 → 1`)
- **多等级可调**：支持随时在控制面板菜单 `7 → 1` -> `3` 自由切换日志级别：
  - `debug`：**深度排错模式**，详细记录 sing-box 进程的每一笔 TCP/UDP 流量、DNS 拦截解析、底层连接与错误堆栈。
  - `info`：**标准生产模式**（默认），输出服务启动、状态切换、关键路由变动。
  - `warn`：仅记录告警与致命错误。
  - `none`：彻底静默模式。
- **全链路日志打通**：sing-box 代理引擎日志已深度实时打通接入系统 `journalctl` 守护日志，无需翻找后台文件，执行 `journalctl -u chainproxy -f` 或在菜单中菜单 `7 → 1` -> `2` 即可实时查看包含底层出入站连接的全部日志！
- **人话网关体检**：提供专用网关体征体检诊断（菜单 `7 → 1` -> `4` 或 `7 → 4` -> `5`），以通俗易懂的中文逐项核验 `ip_forward`、`rp_filter`、策略路由、代理路由表与 `chain0` 虚拟网卡收发字节。

### 11. 🩺 一键系统与网络诊断 (菜单 `7 → 2`)
- 快速全面体检内核版本、网络接口、TUN 设备、默认网关、DNS 解析、防火墙及 systemd 服务状态。

## 💡 它是怎么工作的？

```
你的 VPS 宿主机 / 容器应用
       │
       ▼
【第一层：入口 WireGuard 节点】（建立底层 UDP 隧道，例如摩洛哥节点）
       │
       ▼ (在隧道内部发起 WARP 握手，二次加密)
【第二层：Cloudflare WARP 出口】（向 Cloudflare Anycast 发起握手）
       │
       ▼
【目标公网网站】（看到的是 Cloudflare 分配给第一层节点所在地区的 WARP 出口 IP）
```

**真正杜绝分流错误**：
- 外网抓包只能看到 `VPS -> 第一层 WireGuard` 的通信流量；
- WARP 流量 100% 经由第一层节点中转出境，无旁路泄漏。

## ❓ 常见问题排查 (FAQ)

### Q: 第一层 WireGuard 节点必须是哪些地区的？
**A**: **支持全球任意国家和地区的 WireGuard 节点**。Cloudflare WARP 会根据第一层节点的出口公网 IP，自动分配该地区最近的 Cloudflare 数据中心及当地 WARP IP（例如第一层是摩洛哥，最终出口就是摩洛哥 WARP IP）。

### Q: 第一层显示未通过但 WARP 畅通能上网，正常吗？
**A**: **完全正常**。因为 WARP 是由第一层节点承载的，WARP 能通就 100% 证明第一层隧道正在工作。部分第一层节点本身是中继网关，不支持未经 WARP 封装的纯 HTTP/HTTPS 直连。

### Q: 如何让同局域网的手机、电脑或电视盒子通过本机网关出海？
**A**: 
1. 在控制面板进入 **`7 → 4`** 开启局域网透明网关（系统会自动计算并放行当前网卡实际前缀对应的网段，如 `192.168.1.0/24`），并在提示时按 **`1`** 应用生效。
2. 记下面板显示的本机局域网 IP（例如 `10.82.160.94`）。
3. 在同局域网需要走代理的设备上打开网络设置，切换为「静态 IP (Static)」，将 **默认网关** 填为本机的 IP（`10.82.160.94`），**首选 DNS** 填写为本机 IP 或 `1.1.1.1`，保存后即可无感走代理出海！

### Q: 局域网客户端能 ping 通网关，但访问外网提示 `curl: (6) Could not resolve host` 是什么原因？
**A**: **这是客户端 DNS 配置未修改导致的典型现象**：
- Linux 客户端修改了默认网关（`ip route replace default via 10.82.160.94`），但客户端的 `/etc/resolv.conf` 依然残留着旧局域网路由器的 IP（如 `nameserver 10.82.160.1`）。
- 由于旧路由器和客户端处于同一局域网 `/24` 子网内，客户端发往 `10.82.160.1` 的 DNS 查询通过二层以太网 ARP 广播直接发给了旧路由器，**根本没有经过本机网关**！
- 若旧路由器无法解析外网，客户端就会立即报错 `Could not resolve host`。
- **👉 解决办法**：在客户端执行以下命令，将 DNS 改为公共 DNS 或本机网关即可：
  ```bash
  echo "nameserver 1.1.1.1" > /etc/resolv.conf
  # 或者指定为本机网关 IP:
  # echo "nameserver 10.82.160.94" > /etc/resolv.conf
  ```

### Q: 如何排查网关或代理链路的实时流量与具体报错？
**A**: 
1. 在控制面板进入 **`7 → 1`** -> **`3`** -> 选择 **`1`**，将日志等级切换为 **`debug`**。
2. 此时在终端执行 `journalctl -u chainproxy -f`（或在菜单中菜单 `7 → 1` -> `2`），即可实时看到 sing-box 捕获的每一笔入站请求（来自哪个局域网 IP、请求什么域名、转发至哪条出站路由等全量细节）。

### Q: 启动提示 `open /dev/net/tun: no such file or directory` 怎么解决？
**A**: v1.0.2 版本已内建 `/dev/net/tun` 自动创建与修复机制。如果您运行在 LXC/Incus 等无特权容器内且宿主机未允许 TUN，需在宿主机容器配置文件中添加允许设备直通（如 `lxc.cgroup2.devices.allow = c 10:200 rwm`）。
